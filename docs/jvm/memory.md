# 运行时内存结构

## 总览

```text
┌──────────────── 线程共享 ────────────────┐   ┌────────── 线程私有 ──────────┐
│ 堆 Heap                                  │   │ 虚拟机栈 VM Stack            │
│  ├ 新生代：Eden / Survivor0 / Survivor1  │   │   └ 栈帧：局部变量表、操作数栈、 │
│  └ 老年代 Old                            │   │          动态链接、返回地址   │
│ 方法区 / 元空间 Metaspace                │   │ 本地方法栈 Native Stack      │
│  └ 类元数据、常量池、静态变量(8+在堆)    │   │ 程序计数器 PC                │
└──────────────────────────────────────────┘   └──────────────────────────────┘
        直接内存 Direct Memory（NIO、堆外，不属于 JVM 规范内存区域）
```

| 区域 | 存什么 | 典型异常 |
| --- | --- | --- |
| 堆 | 几乎所有对象实例、数组 | `OutOfMemoryError: Java heap space` |
| 虚拟机栈 | 方法调用的栈帧 | `StackOverflowError`（递归过深）|
| 元空间 | 类信息、方法、常量池（使用本地内存） | `OutOfMemoryError: Metaspace` |
| 程序计数器 | 当前执行的字节码行号 | 唯一不会 OOM 的区域 |
| 直接内存 | `ByteBuffer.allocateDirect` | `OutOfMemoryError: Direct buffer memory` |

> JDK 8 用元空间取代了永久代（PermGen），元空间直接使用本地内存，默认无上限。

## 对象的创建

1. 类加载检查；
2. **分配内存**：指针碰撞（规整堆）或空闲列表；并发时用 **TLAB**（线程本地分配缓冲）避免竞争；
3. 内存清零（字段默认值）；
4. 设置**对象头**（Mark Word、类型指针、数组长度）；
5. 执行 `<init>` 构造方法。

## 对象的内存布局

```text
对象头 Header ： Mark Word（哈希码、GC 年龄、锁状态）+ Klass 指针（开启压缩指针 4 字节）
实例数据       ： 各字段值
对齐填充       ： 补齐到 8 字节倍数
```

## 逃逸分析

JIT 分析对象是否「逃出」方法 / 线程：

- **栈上分配**（实际通过标量替换实现）
- **锁消除**：对象不会被别的线程访问，去掉 `synchronized`
- **标量替换**：拆成基本类型存在寄存器 / 栈上，不创建对象

## 引用类型

| 类型 | 回收时机 | 用途 |
| --- | --- | --- |
| 强引用 | 绝不回收（可达时） | 普通对象 |
| 软引用 `SoftReference` | 内存不足时 | 缓存 |
| 弱引用 `WeakReference` | 下一次 GC | `WeakHashMap`、`ThreadLocal` 的 key |
| 虚引用 `PhantomReference` | 随时，仅用于收到回收通知 | 管理堆外内存 |

## 栈帧与方法调用

- 每次方法调用压入一个栈帧，返回时弹出；
- 局部变量表存放参数与局部变量；
- 栈深度默认约 1 万 ~ 2 万层，由 `-Xss` 控制。
